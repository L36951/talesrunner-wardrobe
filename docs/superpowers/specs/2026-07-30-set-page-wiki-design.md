# 套裝頁：wiki 版面

2026-07-30

將 1,978 個套裝頁由冇樣式嘅裸 HTML，改成 wiki 式版面：右側 infobox、能力值用表格、
頁首導語段落。同時加樣式畀三個列表頁。

已批准嘅視覺參考：`2026-07-30-set-page-wiki-mockup.html`（同目錄，用瀏覽器打開）。
**實作以嗰個檔為準**，本文負責講規則同理由。

## 背景

[前一份 spec](2026-07-30-set-pages-seo-design.md) 交付咗 1,978 個可索引嘅套裝頁，
已經上線。但嗰批頁面**完全冇 CSS** —— 人哋由 Google 撳入嚟，見到嘅係瀏覽器預設樣式
嘅純文字文件，同隔籬個精緻 SPA 判若兩個網站。跳出率會反饋落排名，即係辛苦爭返嚟嘅
流量會白白流走。

揀 wiki 風而唔係跟番遊戲視窗風格，理由唔係美觀：

- **同對手打同一場仗。** 唯一嘅競爭者係 [跑Online 維基（Fandom）](https://talesrunner.fandom.com/zh/wiki/%E8%A3%9D%E5%82%99)。
  人哋搜裝備嗰陣期待見到 wiki 格式；俾佢一個更完整、更新、仲可以一鍵試身嘅 wiki，
  就係直接比較同直接勝出。
- **表格可以比較，bullet list 唔可以。** 搜裝備嘅人多數想知「呢件好唔好、同其他點比」。
- **導語段落係純賺嘅獨特內容**，遊戲視窗風冇位放。

## 範圍

改 `scripts/lib/render-set.mjs` 同 `render-listing.mjs` 產生嘅 HTML，加一個新嘅
`assets/set-page.css`。

**呢個唔係純樣式改動** —— 版面結構同頁面內容都會變，所以 `tests/render-set.test.mjs`
入面斷言 `<ul class="stats">` 嗰幾個測試要跟住改。

明確唔做：

- **唔郁 `index.html`。** 由第一日起我哋就冇碰過個 SPA 內部，唔會為咗樣式破例。
  代價係色值會喺兩處重複，接受，CSS 入面會註明來源。
- 唔加 JavaScript。頁面維持純靜態 HTML + CSS。
- 唔改 `data/items.json`、唔改頁數、唔改 URL、唔改 sitemap。
- 唔處理 351 件「能力值黐咗入 description」嘅上游資料問題（影響 38 頁）。

## 1. 新增內容：導語段落

每版頁首加一段完整句子。呢個係本次唯一新增嘅**文字內容**，其餘都係重排。

模板：

```
{name} 係《跑Online》嘅{類型}套裝，由 {n} 件裝備組成：{成員名，頓號分隔}。
{套裝效果句}{可穿著句}
```

| 變數 | 規則 |
|---|---|
| `{類型}` | `equipmentType === 'avatar'` → `Avatar`；否則 `角色裝備` |
| `{套裝效果句}` | `setStats` 非空 → `著齊全套會觸發套裝效果，`；空 → `呢套裝備冇套裝效果，` |
| `{可穿著句}` | 人數 > 0 → `共 {m} 個角色可以著齊。`；0 → `暫時冇角色可以著齊全套。` |

實例（`setId` 1259）：

> 青花瓷套裝(男) 係《跑Online》嘅角色裝備套裝，由 3 件裝備組成：青花瓷羽毛(男)、
> 青花瓷長筒靴(男)、青花瓷套裝(男)。著齊全套會觸發套裝效果，共 29 個角色可以著齊。

每版約多 60–90 字。對最薄嗰批（目前 382 字）係 +20% 左右，而且係**完整句子而唔係
散碎詞語** —— 同等字數之下，散文對索引嘅幫助大過列表。

成員多過 6 件時，列頭 6 個之後加 `等 {n} 件`，避免導語變成一條長清單。

## 2. 版面

```
┌─ 頂欄：站名 + 導覽 ───────────────────────┐
│ 麵包屑                                    │
│ ══ H1 套裝名 ══════════════════           │
│ 副標：《跑Online》{類型}套裝，共 N 件       │
│ ┌──────────────────┐  ┌─ infobox ─────┐ │
│ │ hatnote（男女版本）│  │ 縮圖列         │ │
│ │ 目錄              │  │ 類型／件數／部位 │ │
│ │ 導語段落           │  │ 套裝效果        │ │
│ │ H2 套裝效果 → 表格 │  │ 可穿著 N/50    │ │
│ │ H2 成員裝備 → 表格 │  │ 另一版本        │ │
│ │ H2 著齊全套 → 表格 │  │ ┌──────────┐  │ │
│ │ H2 可穿著角色      │  │ │ 立即試身  │  │ │
│ │ H2 相關套裝        │  │ └──────────┘  │ │
│ └──────────────────┘  └───────────────┘ │
└──────────────────────────────────────────┘
```

**Infobox 內容**：縮圖列（全部成員 icon）、類型、件數、部位（成員 `subcategory` 去重）、
套裝效果、可穿著 `N / 50 個角色`、另一版本（有先顯示）、試身掣。

**成員裝備表格**欄位：icon、名稱＋描述、部位、能力值。冇能力值嘅格顯示 `—`，
唔好留白。

**能力值表格**：兩欄（名稱、數值），數值右對齊、`tabular-nums`。

**Hatnote** —— 男女對應版本由底部區段搬去頂部，格式：

> 本套裝有女性版本：[青花瓷套裝(女)]。兩者成員裝備完全不同。

「兩者成員裝備完全不同」係事實陳述（76 對之中 76 對成員 ID 完全唔重疊），
唔係推銷語，值得寫出嚟因為呢個正正係兩版分開存在嘅理由。

## 3. CSS 交付

**一個外部檔 `assets/set-page.css`**，唔 inline。

1,978 頁共用同一個檔，第一次載入之後全部快取 —— 玩家連續睇幾個套裝係零額外成本。
Inline 嘅話約 4KB × 1,978 ≈ 多 8MB，而且完全冇快取效果。

檔案由 `assets/` 出（已經係公開靜態目錄），唔經 build script 生成 —— 佢係手寫資產，
唔係產物，所以要 commit 入 repo，**唔可以加入 `.gitignore`**。

### 能力值顏色

`stats` 資料帶住 `green` / `blue` / `red` / `gold`。SPA 嗰四隻色係**為深色 tooltip 設計**，
喺淺底面板上面對比度嚴重不足：

| 語意 | SPA（深底用） | 本頁（淺底用） |
|---|---|---|
| 增益 | `#37c7ff` | `#0f5f9e` |
| 正面 | `#38ef4c` | `#186f2a` |
| 負面 | `#ff4545` | `#b81f26` |
| 特殊 | `#ffe13c` | `#7d5600` |

同色相加深，保持玩家已經識嘅語意，但對白底達到可讀對比。CSS 入面每隻都要註明對應
SPA 邊個值。

## 4. 響應式

Google 用**行動裝置優先索引** —— 佢主要睇手機版嚟排名。而玩家搜裝備大機會用手機。

**你個 SPA 本身唔係手機友善**（固定 1020×708 縮放），但套裝頁可以係，所以要做好：

- 斷點 `820px`：infobox 由右側改為置頂（`order:-1`），闊度 100%，縮圖列由 4 欄變 6 欄
- 表格可橫向捲（`overflow-x:auto`），唔可以撐爆版面
- 內文字級最少 15px，掣高最少 44px

## 5. 列表頁

`/sets`、`/sets/role`、`/sets/avatar` 用同一個 CSS。列表由 `<ul>` 改成多欄版面
（`column-count` 或 grid），令 1,164 條連結唔使碌足一屏。每項顯示套裝名同件數。

## 6. 對現有測試嘅影響

`tests/render-set.test.mjs` 目前 17 個測試，其中斷言 HTML 結構嗰幾個要改：

- `lists the set bonus` / `shows the summed member stats` —— 由 `<ul class="stats">` 改為表格
- 新增：導語段落存在且含成員名
- 新增：infobox 存在且含件數
- 新增：`<link rel="stylesheet" href="/assets/set-page.css">` 存在
- 新增：hatnote 只喺有對應版本時出現

**唔可以改嘅斷言**（呢啲係前一份 spec 嘅硬要求，改咗就係退步）：

- 剛好一個 `<link rel="canonical">`，而且自我指向
- 圖片用絕對路徑 `/assets/itemimage/`
- JSON-LD 唔可以被標走
- 冇角色著得齊時要出提示

## 7. 風險

**改嘅係已上線嘅頁面。** 1,978 頁已經 deploy，Google 可能已經開始爬。版面大改唔會
影響索引（URL、標題、canonical 全部唔變），但要確保**文字內容只增不減** —— 任何
現有文字消失都係倒退。實作完要對比改動前後嘅純文字長度，確認每一版都冇縮水。

**CSS 檔要入 repo。** `assets/` 目錄目前全部係由遊戲客戶端解包出嚟嘅資產，加一個
手寫 CSS 入去係新做法 —— 日後有人重新解包素材時要記得唔好連佢一齊覆蓋。

已驗證兩件事，唔使再擔心：`git check-ignore` 確認 `assets/set-page.css` 唔會被
`.gitignore` 擋；`scripts/build-seo.mjs` 嘅 `rmSync` 只清 `set/` 同 `sets/`
（第 61–62 行），完全唔碰 `assets/`。
